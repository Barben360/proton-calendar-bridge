# M8 MCP adapter Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** AI agents read and edit the Proton calendars of every granted account through MCP: remote `/mcp` on the daemon's listener with per-agent bearer tokens, and stdio `pcb mcp`, which relays to a running daemon or serves the session itself. Login over stdio happens with the secrets typed by the person, never by the agent.

**Architecture:**
- **C0 `internal/ical`:** recurrence expansion (`Expand`), a decoded event view (`DecodeEvent`), field edits as patches of the stored VCALENDAR (`NewEvent`, `ApplyEdit`, `DeleteOccurrence`).
- **C3 `internal/service`:** an `Agenda` interface per account (occurrences, one event, free/busy, create/update/delete) on `*Local`, through `Hub.Agenda`. Also the per-account MCP switch (`state.json` `mcp`, loop rule "either adapter on"), and the serve lock naming the daemon's kind.
- **`internal/access`:** `TokenStore` for `<state>/mcp-tokens.json` (hash only).
- **A4 `internal/mcp` (new):**
  - grants;
  - one SDK server per session with the tools its grant allows;
  - the HTTP handler (remote and control socket);
  - the stdio runner;
  - the audit log;
  - the loopback login page (`internal/mcp/loginpage`).
- **`internal/daemon`, `internal/ctl`:**
  - a mux puts `/mcp` beside CalDAV on the listener when `[mcp] remote` is on, and beside `/v2` on the control socket always;
  - `NoListener` for the session daemon;
  - `ShowLogin` for `pcb-ui`.
- **`internal/cli`:**
  - `pcb mcp` (probe, then relay or become the session daemon);
  - `pcb mcp token add|list|remove`;
  - `pcb account mcp on|off`;
  - status and doctor lines.
- **`internal/ui`:**
  - the wizard behind an interface, so the login page reuses it;
  - the MCP toggle per account;
  - `ShowLogin`.

**Tech Stack:**
- Go 1.27;
- `github.com/modelcontextprotocol/go-sdk` ≥ v1.8.0 (MCP 2025-11-25), exact version pinned by Task 1 (E19);
- RRULE: the library or our own code that Task 2 (E16) chooses.

**Spec:**

## Global Constraints

- `make lint test` passes after every task; every task starts with a failing test that bites (AGENTS.md).
- `cmd/pcb` stays `CGO_ENABLED=0`; `cmd/pcb/arch_test.go` still passes; no `fyne.io/` package in `go list -deps ./cmd/pcb`.
- `internal/mcp` imports only the standard library, `internal/service`, `internal/exitcode`, `internal/access` (token types), its own `internal/mcp/loginpage` (which uses `internal/loginflow`) and the SDK. It never imports `internal/proton/...`, `internal/store/...`, `internal/ical`, `internal/cli` or `internal/ui`. Add `internal/mcp/arch_test.go` (Task 9). *Amended at build time (rulings R18, R21): this line first allowed `internal/ui` for the wizard in `loginpage`; that import would close the cycle ui → daemon → mcp → ui, so the login state machine moved to `internal/loginflow`, which `internal/ui` and `internal/mcp/loginpage` both use, and the arch test forbids `internal/ui`.*
- `internal/ctl` keeps its import rule (stdlib, `service`, `output`, `exitcode`, `buildinfo`): it receives `/mcp` as an `http.Handler`.
- No secret in any tool argument, tool result, MCP log message, audit line, error, recorded file or argv. That covers: Proton password, 2FA code or otpauth secret, CAPTCHA token, CalDAV password, an MCP token after `token add` prints it, a login-page URL in a log.
- Token format `pcbm_` + 43 base64url characters (32 random bytes); stored as salted SHA-256 only, never sealed or shown again.
- Limits:
  - 1000 occurrences per series per call;
  - range ≤ 366 days;
  - `limit` default 100, max 500;
  - descriptions cut at 4 KiB in lists and 64 KiB in `event_get`;
  - render budget 2000 objects per call [call; design §7 left the number open];
  - login cooldown 60 s per MCP session;
  - login page TTL 5 min;
  - nonce 128 bits;
  - `pcb mcp` lock-race back-off ≤ 10 s total.
- Tool names, exactly:
  - `status`, `calendars_list`, `free_busy`, `events_list`, `event_get`, `events_search`;
  - `event_create`, `event_update`, `event_delete`;
  - `login`, `logout`.
- Capabilities, exactly: `freebusy`, `read`, `write`, `delete`, `login`, `manage`.
  - Profiles: `read-only` = `read` + `login`; `full` = all six.
  - `login` and `manage` are refused on tokens.
- Error classes in tool errors, exactly: `must-act`, `retry`, `refused`, `conflict`, `not-found`.
- Config: `[mcp] remote = false`, `[mcp] timezone = ""`, strict decoding like every section.
- Commit subjects: `<emoji> <imperative>` (AGENTS.md).
- Live Proton calls only on the test account, through `scripts/live/run.sh`.
- RDATE is never stored: Proton refuses it at write time (`ical.RDate` refusal), so expansion handles RRULE, EXDATE and overrides. This corrects design §5.6, which listed RDATE.

## Review Focus

1. **A wall-clock time with no offset** (`"2026-11-14T15:00"`) or a bare date from an agent is read in the `tz` argument, else `[mcp] timezone`, else the process zone. The zone used is echoed in the result. A malformed time is a `refused` error naming the argument, never a silent UTC. Test in Task 9.
2. **Daylight-saving transitions:** a weekly event at 02:30 Europe/Paris across 2026-03-29, and an all-day event viewed from a zone 10 h away, give the occurrences Proton's web app shows. Test in Task 3.
3. **A stale ETag** after a Thunderbird edit gives a `conflict` and nothing is written. Test in Task 6 (service) and Task 11 (tool).
4. **A daily series over a 366-day range** with `limit` 500 returns 500 occurrences, `truncated: true` and a cursor that continues without repeats or gaps. It does not time out. Test in Task 6.
5. **An account removed, signed out or switched `mcp off` while a session is open:** the next call answers like an account outside the grant (`not-found`, "no account X"). No stale data, no panic. Test in Task 9.

type Scope string

// Fields is an edit: nil leaves a field as it is; a pointer to "" clears a text field.
type Fields struct {
	Summary, Description, Location *string
	Start, End                     *Time
	RRule                          *string // "" removes the recurrence
	Alarms                         *[]int  // minutes before; replaces every relative alarm
	Busy                           *bool   // TRANSP OPAQUE / TRANSPARENT
}

- Rules (design §5.6):
