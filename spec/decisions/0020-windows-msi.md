# 0020 — Windows installer: a per-user WiX MSI

- **Date**: 2026-11-15
- **Decided by**: author (an MSI before the next release; `pcb-ui` required, `pcb` optional on the user's `PATH`; a Start-menu shortcut; "Start at login" in the installer; unsigned, SmartScreen warns as for the zip; WiX 7.0.1 with its OSMF EULA accepted), the rest the agent's calls, approved by the author (design `spec/designs/2026-11-15-windows-msi-design.md` §4)
- **Status**: accepted, built (`packaging/windows/pcb.wxs`, `scripts/release/mkmsi.ps1`, `scripts/win/msi-smoke.ps1`, `make msi`); checked live 2026-11-15 (`spec/HUMAN-CHECKS.md` step 13, `spec/experiments/W2-windows-msi-live.md`; one fix in, SmartScreen on a real browser download for the author to confirm); amends 0018 ("Next" 1, the MSI) and SPEC §13 ("Platforms")

Each release ships `pcb_windows_amd64.msi` next to the zip, which stays as the portable option. It installs the bridge for one Windows user, with no administrator prompt.

- **Tool [author].** WiX Toolset 7.0.1 exactly, with `WixToolset.UI.wixext` and `WixToolset.Util.wixext` 7.0.1, on a Windows runner. Every `wix` command, `wix build` and `wix extension add` alike, passes `-acceptEula wix7`: the author accepted the Open Source Maintenance Fee EULA (2026-11-15). `scripts/release/mkmsi.ps1` refuses any other WiX version; `make msi` builds `bin/pcb_windows_amd64.msi` and runs the ICE checks.
- **Scope [call].** `Package Scope="perUser"`, installed in `%LOCALAPPDATA%\Programs\pcb` (`LocalAppDataFolder\Programs\pcb`) and nowhere else: another `INSTALLFOLDER` is refused (`pcb installs in %LOCALAPPDATA%\Programs\pcb only: leave INSTALLFOLDER unset.`). No custom action elevates.
- **Features [author].** `App`: `pcb-ui.exe` and the shortcut, `AllowAbsent="no"`. `Cli` ("pcb (command line)"): `pcb.exe` and a user `PATH` entry (`Environment Name="PATH" Action="set" Part="last" System="no"`), on by default, deselectable in the features screen or with `REMOVE=Cli` (the installed version's MSI: another version's then installs nothing) / `ADDLOCAL=App,Cli` (any version's: with another, it is an upgrade, which installs only the features named; `ADDLOCAL=Cli` alone would remove `pcb-ui`).
- **PATH entry [call].** `[LocalAppDataFolder]Programs\pcb`, without the trailing `\` of `[INSTALLFOLDER]`: Windows Installer skips an entry `PATH` already holds only when the text is the same (any case), and removes it at uninstall. Written that way, it matches an entry a zip user added by hand, so it is not doubled. This is why the folder is fixed.
- **Screens [call].** `WixUI_FeatureTree`, plus a "Start at login" screen between the features and the ready screen (at a first install or an upgrade); the licence is the repository's MIT `LICENSE` as RTF, generated by `scripts/release/licensertf.py` and checked against `LICENSE` by `make release-test`; the finish screen's "Launch pcb-ui" box, ticked, starts it.
- **Start at login [call].** A public property `STARTATLOGIN`: `1` turns it on, any other value leaves it off. It defaults to `1` at a first install; at an upgrade it is `1` only when the Run value starts this install's `pcb-ui.exe`, so the upgrade keeps what `pcb-ui`'s switch left; the command line wins over both. The value is not a component: a deferred `reg.exe` (WixQuietExec, as the user) writes `HKCU\Software\Microsoft\Windows\CurrentVersion\Run` `pcb-ui` = `"[INSTALLFOLDER]pcb-ui.exe" --background` (exactly `internal/runkey`'s data) at an install or upgrade with `STARTATLOGIN=1`. It deletes the value at the uninstall (not the old product's uninstall inside an upgrade, nor another version's MSI given a `REMOVE` that leaves it no feature), or at an install with the box unticked, and only when the value found contains this install's quoted `pcb-ui.exe`, so another copy's value stays. A repair or a feature change does neither. A failed write does not fail the install: the user turns it on in `pcb-ui`'s Settings.
- **Shortcut [author; call: the ID].** One non-advertised shortcut `Start Menu\Programs\pcb-ui.lnk` to `pcb-ui.exe`, with `System.AppUserModel.ID` = `io.github.barben360.pcb-ui`, the Fyne app ID `pcb-ui` uses (`cmd/pcb-ui/main_desktop.go`), so Windows names its toasts after `pcb-ui`.
- **Running `pcb-ui` [call].** Restart Manager closes it before files are replaced or removed; `pcb-ui` drains on the session-end message as at a sign-out (checked on the VM at upgrades, repairs and uninstalls, silent and with the screens, from Settings too: exit 0, no reboot asked). No `util:CloseApplication`. Nothing starts it again: it is not registered with `RegisterApplicationRestart`, although the screens' `Files in Use` dialog says the installer will "attempt to restart" it.
- **Upgrades [call].** `MajorUpgrade AllowSameVersionUpgrades="yes"`, a fixed `UpgradeCode` (`6DBB5FA8-C216-4CE9-B535-E35923F221DC`, constant forever), a downgrade refused with `A newer version of pcb is already installed. Uninstall it first to install this one.` `ProductVersion` is the tag's `X.Y.Z` (`vX.Y.Z[-…]`, `scripts/release/check.sh msi-version`), `0.0.0` for a build that is not a tag.
- **Over a zip [call].** A zip unzipped into `%LOCALAPPDATA%\Programs\pcb` holds the same names. Windows Installer keeps a file of an equal version (`pcb-ui.exe`'s is the tag's `X.Y.Z.0`, so an rc zip's equals the final MSI's: live check F2), so each component deletes its `.exe` before the copy (`RemoveFile On="install"`), and the `App` component removes the zip's `LICENSE` and `README.md` at the uninstall: the folder is the installer's.
- **Uninstall [call].** Removes the program files, the shortcut, the `PATH` entry and the Run value (as above); keeps `%APPDATA%\pcb` and `%LOCALAPPDATA%\pcb`. Wiping the data stays `pcb uninstall --delete-data`, run before the uninstall.
- **Release [call].** The MSI is built from the release's own binaries, listed in `checksums.txt` and attested like every asset; `scripts/win/msi-smoke.ps1` installs, checks, changes, repairs, upgrades and uninstalls it silently in CI on every pull request and on the release's asset before publishing.

Why:
- Per-user needs no administrator, and matches what it installs next to: the Run value, the user `PATH` and pcb's data are all the user's.
- WiX gives the feature tree that makes `pcb` deselectable; `wixl` (msitools) builds on Linux but has no WiX UI, and a PowerShell script has no uninstall entry, no repair and no shortcut ID.
- A registry component would bring "Start at login" back: a repair with the default `/fomus` rewrites a component's HKCU values, which a smoke check against such a build showed; the custom actions run only at an install, an upgrade and the uninstall.
- An MSI version has three fields: `v0.2.0-rc.1` and `v0.2.0` are both `0.2.0`, and the final must replace the candidate.

Consequences and limits:
- Unsigned: SmartScreen warns about an unknown publisher until Authenticode signing.
- After a silent upgrade or a repair `pcb-ui` stays closed until the next sign-in (with "Start at login" on) or a start from the Start menu; at an upgrade with the screens, "Launch pcb-ui" starts it (a repair's finish screen has none).
- Every repair replaces both programs (the `RemoveFile` above), so it closes a running `pcb-ui` even when its files were intact.
- The Run value's write has no rollback action: an install that fails after it leaves the value.
- The `PATH` entry is matched as text: a hand-made entry with a trailing `\` or a `%VARIABLE%` gets a second one beside it, and the uninstall removes a hand-made entry identical to the installer's (its folder is gone anyway).
- Installing a candidate over its final release is accepted too (same version). WiX cannot make a byte-identical MSI: the checksum and the attestation cover it. ICE61 (same-version upgrades) and ICE91 (a per-user package) are expected warnings.
- A standard user's SSH session cannot reach the Windows Installer service (`msiexec` exits 1601): MSI steps on the VM run in the user's console session (`docs/development.md`).
- Over a zip unzipped into the same folder, the Run value of that `pcb-ui.exe` counts as the installer's, and the zip's programs are replaced (above); the docs still say to remove the zip first (`.\pcb.exe uninstall`, then its folder and `PATH` entry). A zip's `pcb.exe` stays when `pcb (command line)` is unticked.
- Cost if wrong: `packaging/windows/`, `scripts/release/mkmsi.ps1`, `scripts/win/msi-smoke.ps1`, `make msi` and the Windows MSI jobs. The `UpgradeCode` can never change: a new one would install a second product beside the first.
