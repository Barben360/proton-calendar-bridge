# 0013 — CalDAV credentials can be shown again (Proton Bridge model)

- **Date**: 2026-11-12
- **Decided by**: author (proposed by the agent during M5)
- **Status**: accepted; amends M3-R17 ("printed once, salted hash only")

CalDAV app passwords stay generated by pcb and persistent, but they can be shown again at any time, as Proton Mail Bridge shows its bridge password:
- the first successful `pcb login` creates a client named `default` when no client exists, so a fresh install has working credentials with no extra step;
- `pcb client show [NAME]` prints what a CalDAV client needs: URL, username (the client's name; any username is accepted), password and, over TLS, the certificate fingerprint;
- `pcb client rotate NAME` replaces a password (the old one stops working at once);
- `pcb client add NAME` keeps giving each device its own, separately revocable password.

Why: a user exposing pcb on a local network needs credentials they can look up again, without rotating them, and a later UI needs the same function behind the control socket.

Security: each password is kept sealed with the key that already protects the Proton session (`secrets.sealed`), beside the salted hash used for the constant-time check. Whoever can read pcb's state directory and its key could recover the CalDAV passwords; that same access already exposes the Proton session, which is more sensitive, so the exposure barely changes. Passwords never appear in logs, argv or errors; `--json` carries one only when asked (`--reveal`). Clients made before this decision keep only their hash: `show` says the password cannot be shown and names `pcb client rotate`.
