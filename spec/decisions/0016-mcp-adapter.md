# 0016 — An MCP adapter for agents, over stdio and remote

- **Date**: 2026-11-13
- **Decided by**: author (an MCP server in `pcb`, stdio and remote; read-only or more by configuration; login inside MCP; multi-account; header-capable clients with one bearer token per agent, no OAuth; stdio relays to a running daemon or serves the session itself; never a login through remote MCP; a per-account MCP switch), the rest the agent's calls (design `spec/designs/2026-11-13-mcp-design.md`, and the implementation plan, not published)
- **Status**: accepted, built in M8 on 2026-11-13 (branch `m8-mcp`; live session run 2026-11-13/14, `spec/HUMAN-CHECKS.md` step 10, `spec/experiments/M8-live.md`; what was built: SPEC §12, the differences from the design: SPEC §18); amends 0007 (MCP was not planned), 0014 (one adapter switch per account becomes two) and SPEC §12's note "agents never on the control socket"

`pcb` gains A4, an MCP adapter over `service` like CalDAV, built on the official Go SDK (`github.com/modelcontextprotocol/go-sdk`, pure Go, `pcb` stays `CGO_ENABLED=0`).

- **Three entries, one server.** Remote: `/mcp` on the daemon's listener (`[mcp] remote = true`; TLS whenever the bind is not loopback), one `pcbm_` bearer token per agent, hash-only, shown once. stdio: `pcb mcp` relays the session to a running daemon's control socket (`/mcp` route), or, when none runs, runs the daemon machinery itself for the session (kind `mcp`, control socket, no network listener). Writes keep running only during Serve (M4).
- **Grants.** Capabilities `freebusy` < `read` < `write`, plus `delete`, `login`, `manage`, scoped by account and optionally calendar. `login` and `manage` exist only over stdio. Amended 2026-11-19, by the author: a delete or sign-out the person cannot confirm (the client declares no form elicitation) is refused unless the grant holds the opt-in capability `unconfirmed-delete` (implies `delete`; a token stored before it has none, so keeps the refusal); `full` does not include it. Rejected: a `confirm: true` argument (an injected instruction sets it as easily), and the `delete` grant alone (too easy to give without knowing the client cannot ask). Amended 2026-11-25, approved by the author: an `event_update` that removes occurrences of a series after now is a delete. Within a two-year horizon that is fewer occurrences after now, or the series ending sooner; past the horizon, where nothing is counted, an endless series given an end, left without a rule, made sparser or postponed, or a far-reaching stored series whose end changes, removes an uncountable number. It needs `delete` (elicitation never stands in for the grant), then the person's confirmation or `unconfirmed-delete`, as a delete does; a change that removes nothing keeps needing `write` alone. A start move is tolerated up to one period of the original; a series that cannot be expanded counts as losing occurrences. Detection is the agenda's dry run (`internal/service`), not the adapter. Rejected: asking without the `delete` grant (it widens what the person chose), a count-only rule (a denser rule that ends earlier beats it), and an unbounded start tolerance (postponing a series by years). Consequence: a `write`-only token can no longer end, shorten, thin out or postpone a series. stdio profiles: `read-only` (read + login) and `full` (the default since 2026-11-14, by the author: it was `read-only`).
- **Login without secrets in the agent.** `login(username)` (stdio only) raises `pcb-ui`'s wizard, or opens a single-use page on 127.0.0.1 in the process that owns the accounts; the person types password, 2FA code and CAPTCHA there. Remote agents never get a login tool. (Built: the wizard and the page share one login state machine, `internal/loginflow`; `internal/mcp` does not import `internal/ui`.)
- **Per-account switch.** `pcb account mcp on|off` beside `caldav`; an account's loop runs while either is on; `mcp off` hides the account from every agent.
- **Control socket.** Agents reach it only through its `/mcp` route, under the socket's same-UID trust, never through `/v2` routes. This replaces SPEC §12's note "agents never on the control socket". Over stdio the profile is a guard rail, not a boundary; over remote the token is a boundary.

Why:
- Decision 0004: agents are the long-term main consumer, and they need the full event model that CalDAV flattens.
- No daemon as a prerequisite for a local agent, without reopening M4's single-writer invariants (a per-call direct mode was reviewed and dropped).
- Secrets typed by the person, never passed through a model or its transcript (AGENTS.md "no secrets anywhere").

Consequences and limits:
- While a `pcb mcp` session serves a state, `pcb serve` and `pcb-ui` refuse to start (they name kind `mcp`); a hand-over is a later improvement. With a system-scope unit installed, `pcb mcp` does not serve and points to remote `/mcp`.
- Headless (remote) accounts are logged in with `pcb login` or `pcb-ui` only.
- New core work: event view, recurrence expansion, patch edits (no exception dropped silently).
- Cost if wrong: the `internal/mcp` package and the switch; the event layer stays useful to any later adapter.
