## 13.9 The MSI over a zip unzipped into the same folder: FAIL when the versions were equal (F2), PASS from an older zip; PASS on the fixed MSI

- 13:39Z, ssh then console. A zip made as a release's (`pcb.exe`, `pcb-ui.exe`, `LICENSE`, `README.md`; v0.1.0 has no Windows zip, so a build of this commit with `VERSION=v0.1.0`), with the Mark of the Web, `Expand-Archive`d into `%LOCALAPPDATA%\Programs\pcb`; Run value `pcb-ui` = `"<install folder>\pcb-ui.exe" --background` (the data `pcb-ui` writes); `pcb.exe version`: `pcb v0.1.0 (commit …)`; `pcb doctor`: `✓ start at login: starts <install folder>\pcb-ui.exe`. The MSI holds this commit's build `v0.1.0-23-g425b7d6`, whose `pcb-ui.exe` has the same Windows file version, `0.1.0.0` (the tag's three numbers and 0), as the zip's.
- `msiexec /i <msi> /qn /l*v`, console: exit 0. Log: `pcb.exe`: `Overwrite; … Existing file is unversioned and unmodified - hash doesn't match source file` (replaced: hash equal to the MSI's, `pcb version` now `v0.1.0-23-g425b7d6`); **`pcb-ui.exe`: `Won't Overwrite; … Existing file is of an equal version`: the zip's `pcb-ui.exe` stayed** (its hash and `pcb-ui --version` still the zip's `v0.1.0 (commit …)`), so the folder held the MSI's `pcb.exe` beside the zip's `pcb-ui.exe`. Run value = the MSI's `pcb-ui.exe` (the same path), `pcb doctor` `✓ start at login: starts <install folder>\pcb-ui.exe`.
- `msiexec /x <msi> /qn`: exit 0; no Run value, no shortcut, the user `Path` as before, `pcb.exe` and `pcb-ui.exe` gone (the zip's `pcb-ui.exe` with them); the zip's `LICENSE` and `README.md` left in the folder (not the package's files).
- 13:40Z, the same with a zip of an older version (`VERSION=v0.0.9`, file version `0.0.9.0`): `pcb-ui.exe`: `Overwrite; … Existing file is a lower version`, `pcb.exe` as above: both hashes equal the MSI's, `pcb-ui --version` the MSI's; Run value and `pcb doctor` as above; the uninstall leaves only `LICENSE` and `README.md`. **PASS**.
- When it happens: a zip and an MSI of the same `X.Y.Z` with different binaries (a release candidate's zip, then the final release's MSI; any two builds from the same tag, as `v0.1.0-23-g…` and `v0.1.0` here, both `0.1.0.0`). A zip and an MSI of the same release hold the same bytes, and a newer MSI over an older zip replaces both files. `docs/install.md` already says to remove the zip first.
- **Run again on the fixed MSI** (14:05Z, same day). The fix: each component deletes its `.exe` before the copy (`RemoveFile On="install"`), and the uninstall removes the zip's `LICENSE` and `README.md`. The MSI built on the VM from the fix's sources, from binaries `VERSION=v0.2.0-rc.1` (`pcb-ui.exe` file version `0.2.0.0`), `-Version 0.2.0`, SHA-256 `F9EEB4F6…6C22ED02`; the zip, the four files of a build with `VERSION=v0.2.0` (another build, the same file version `0.2.0.0`), with the Mark of the Web, `Expand-Archive`d into the folder; Run value set as above. `msiexec /i <msi> /qn`, console: exit 0; log `File: …\pcb-ui.exe; To be installed; … No existing file` and the same for `pcb.exe` (the zip's copies deleted first); both hashes equal the MSI's binaries', `pcb version` and `pcb-ui --version` print `v0.2.0-rc.1`; Run value the installed `pcb-ui.exe`; `pcb doctor` `✓ start at login: starts <install folder>\pcb-ui.exe`. `msiexec /x <msi> /qn`: exit 0, **no install folder left** (the zip's `LICENSE` and `README.md` gone with it), no Run value, no shortcut, the user `Path` as before. **PASS**. The smoke (`scripts/win/msi-smoke.ps1`) now checks the same with a copy of the MSI's own binaries plus one byte (the same file version, other bytes), and a repair after it.
